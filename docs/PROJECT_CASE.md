# WeRead AI 项目案例

## 一句话定位

一个嵌入微信读书阅读场景的本地 AI 阅读记忆工具，用章节节点、阅读回顾和 Obsidian 导出，减少长篇阅读中的进度断裂与知识沉淀成本。

## 用户问题

长篇阅读中，用户容易忘记上次读到哪里、难以快速回顾情节，也很难把划线内容整理成可复用的知识笔记。工具需要贴近阅读页面，同时保留用户对节点和导出内容的控制权。

## 核心方案

- Chrome Manifest V3 扩展注入微信读书阅读页，展示侧边栏和进度条节点。
- FastAPI 本地服务负责章节分析、阅读回顾、笔记整理和全书总结。
- Chrome Storage 保存书籍节点、阅读历史和接口配置。
- Obsidian 作为知识沉淀出口，AI 只负责整理，用户仍可手动编辑节点和配置路径。

## 个人工作边界

独立完成需求拆解、阅读页交互设计、浏览器扩展与 FastAPI 服务的边界划分、接口设计、Prompt 编写、本地状态管理和运行验证；项目定位为个人原型与本地工具，不宣称为商业化产品或公开稳定服务。

## 当前验证

- `weread_api.py` 语法检查通过。
- 本地 FastAPI 服务可启动。
- `GET /api/health` 返回 `200`。
- `GET /openapi.json` 返回 `200`。
- 未配置 Gemini Key 时，AI 接口会返回明确的配置错误，不伪造成功结果。

## 当前边界

- 章节目录和划线内容依赖微信读书网页 DOM，网站结构变化后需要调整选择器。
- AI 功能依赖用户自己的 Gemini API Key。
- Obsidian 导出依赖本机路径，因此当前以本地运行和 GitHub 源码展示为主，不直接公开部署。
- 尚未完成真实微信读书页面上的跨页面兼容性评测，简历不写成大规模线上验证。
